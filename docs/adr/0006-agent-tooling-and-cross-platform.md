# Agent tooling and the Windows mirror

Agent tools run on Linux hosts and are mirrored to Windows, so shared config must avoid Nix store paths.

- The Windows mirror installs real copies instead of links: Windows cannot follow WSL symlinks into `/nix/store`. Git config carries only sections without store paths (Git for Windows' system config already provides LFS and the credential manager), and its includes go last so they override `[user]`, because `toGitINI` sorts sections alphabetically. `core.symlinks` is set true because the Git for Windows installer sets it false system-wide, which checks symlinks out as text files; Developer Mode lets them be real links. The same folder is `/mnt/c/...` in WSL and `C:/...` to Git for Windows.
- Claude Code settings outside `managedState`, the git guardrails hook (plain bash, run under Git Bash on Windows) and the portable Codex settings, which leave out MCP servers, carry no store paths, so other platforms reuse them. Codex reads only `~/.codex/AGENTS.md`, never `~/.agents/AGENTS.md`.
- `agent-shell` points GUI sessions at a fixed path, not a store path: GUI sessions snapshot their environment at login, so the variable never changes and switches only rewrite the file.
- External skills are fetched with `nix-prefetch-git` hashes covering exactly the locked sparse paths, so `fetchzip` is never a fallback and a path mismatch fails early instead of as a hash mismatch.
- Secrets reach agents through the environment, never the store: CLIProxyAPI credentials are generated once at activation, and the typesafe key is loaded from sops into interactive shells that agents inherit.
- zaza installs the canary because agents read untrusted input, and a prompt-injected agent reaches for stolen keys first. A polkit rule grants hermes `org.freedesktop.systemd1.manage-units`, which run0's transient root unit asks for, so hermes can `just switch` unattended.
- Hermes' dev workspace authenticates `gh` only from the sops-rendered `GITHUB_TOKEN` and clones nixos-config at the root of the hermes home, deliberately outside `~/dev`, as a trust boundary. The bootstrap runs in the system manager so it can order after `network-online` and the NixOS-level sops render. hermes-talk's Echo link runs as its own unit, so an Echo reboot or crashed link restarts it without touching the gateway, and it reuses the gateway's environment plus a PATH that also reaches the system `openhome`, because `home_control` is offered only where that CLI is found.
- `binary-cache` sets a 5 s `connect-timeout`, so off the tailnet, where zaza is unreachable, substitution skips it quickly instead of stalling; zaza is an extra substituter behind cache.nixos.org.
