# Specialist agents own their skills

A specialist agent carries skills and MCP servers that no other agent sees, because every installed skill's description and every MCP tool's schema costs context on every turn in every harness, and a domain pack like the 94 Blender skills or fal's media tools is useless outside its domain. Bundles are listed in `agents/skill-sources/bundles.nix` by bundle name, so several repos can feed one bundle; they are fetched and locked like skills and never merged into `~/.agents/skills`. Bundling clears `disable-model-invocation`, because a specialist works from a brief with no human to type a skill's slash command. `agent-skills` pairs each role prompt in `agents/specialists/<name>.md` with its bundle, if any, as `config.lib.agents.specialists.<name>`.

- A specialist is an `agents.specialists.<name>` entry (the `specialists` aspect), declared in the aspect of the app it drives: `blender` and `kaigen-studio` declare theirs, and `agent-specialists` holds those with no app aspect (media, cloudflare, ui, qa). Its `harnesses` say what runs it, Pi alone by default; `pi-specialists`, `claude-specialists` and `antigravity-specialists` each turn the same entry into a launcher and a T3 instance. On Pi it becomes the command `pi-<name>`: Pi run as the main agent with only its bundle (`--no-skills --skill`), its tools, its role prompt, no context files or prompt templates, and its own agent directory `~/.pi/specialists/<name>`.
- The specialist's MCP servers live only in its agent directory's `mcp.json`, which Nix owns outright because nothing else writes it (OAuth tokens go to `mcp-auth.json`), with tools declared directly and filtered to its servers by `--tools mcp__<server>__*` (Pi turns `-` in a server name into `_`). `--no-approve` keeps a trusted project's `.pi/` files from replacing those servers. A separate agent directory is the only way Pi keeps one session's servers out of another, and it also keeps each specialist's MCP sign-ins and sessions apart: `pi-<name> mcp login <server>` signs in once. Provider logins are shared instead: each specialist's `auth.json` links to the main Pi's, so one `/login` puts every provider's models (Codex's GPT models too) on every specialist, and Pi locks token refreshes on the resolved file. Its settings reuse the main Pi's Claude provider, and the command passes the model as `--model` instead of a settings default: Pi picks a default model before the provider's async `claude auth status` check finishes, so about a third of runs found no model or fell back to another logged-in provider, while an explicit `--model` waits for the check. A caller's own `--model` still wins.
- It is not a pi-subagents agent, because since 0.43 pi-subagents runs every child through `workflowScript`, which needs `node:v8` promise hooks that the Bun-built Pi lacks. As a subagent it would not be isolated either: Claude Code's `skills:` field only preloads and Codex agents can only disable inherited skills.
- The Blender specialist drives the headless Blender CLI, not Blender MCP: the skills' real work is `bpy` code either way, and the MCP add-on needs a running GUI Blender listening on an unauthenticated socket that executes any Python it receives. The role prompt translates the skills' MCP calls into CLI steps and preview renders.
- T3 Code, the only interface in use, runs each specialist as its own provider instance per harness (the driver's `binaryPath`), so an orchestrator delegates to it as a child thread the user can watch; every session's instructions list the specialists through `agents.extraInstructions`. Each harness aspect declares its instances through `t3code.providerInstances`, which `t3code-settings` merges into `~/.t3/userdata/settings.json` at activation for every user that declares one, desktop or headless service alike, instead of owning the file, because T3 writes the rest of it. The merge runs after `linkGeneration`: writing the file makes T3 probe every instance at once, and a probe that runs while Home Manager still swaps a specialist's `settings.json` and `auth.json` caches that instance without its Claude models.
- Design skills (jakubkrehel, emilkowalski, vercel-labs/ui) belong to the `ui` specialist alone; general sessions hand design decisions to the `ui` specialist through the specialist list.
- Blender and Kaigen also run on Antigravity as `agy-<name>`, because `agy` is how Gemini models get their skills while Pi covers Claude and Codex; Pi stays the default, so the two are listed together and one domain never has two unexplained owners. T3 gives every Antigravity instance a private profile and links its skills and rules from `$HOME/.gemini`, so the instance's `HOME` is `~/.antigravity/specialists/<name>` and the wrapper restores the real one before `agy` starts. T3 accepts a custom executable only when its file is called `agy`. The wrapper also writes the specialist's MCP servers into the profile, which T3 otherwise leaves without any, and links the Google token of T3's `antigravity` instance, so one sign-in there serves every specialist. `agy` keeps its built-in skills and reads the project's own `AGENTS.md` and `.agents/skills`, neither of which it has a flag to turn off.
- UI runs on Claude Code instead of Pi, as the top-level command `claude-ui`: an empty `--setting-sources` drops the user's and project's settings, skills, plugins and instructions, `--plugin-dir` adds the bundle (so skills are named `ui:<skill>`), and `disableBundledSkills` with the built-in plugins off leaves nothing else. It keeps the main `~/.claude` directory, because Claude rotates its refresh token and a linked credentials file could be replaced by one session and leave the other signed out. The role prompt comes from a `SessionStart` hook in that plugin, which also fires on resume and compaction, because T3 sets the appended system prompt when it initializes a session and so discards `--append-system-prompt`. T3 passes its own `--settings` and `--setting-sources`, so the wrapper merges the former, T3's values winning, and repeats the latter last. Only subcommands such as `auth status` pass through untouched.
