# Specialist agents own their skills

A specialist agent (Blender today) carries a skill bundle that no other agent sees, because every installed skill's description costs context on every turn in every harness, and a large domain pack like the 94 Blender skills is useless outside its domain. Bundles are listed in `agents/skill-sources/bundles.nix`, fetched and locked like skills, and never merged into `~/.agents/skills`; `agent-skills` pairs each bundle with its role prompt in `agents/specialists/<name>.md` as `config.lib.agents.specialists.<name>`.

- The Blender specialist is the `pi-blender` command: Pi run as the main agent with only its bundle (`--no-skills --skill`), no context files, MCP or prompt templates, and the four file and shell tools. Pi is the one harness here that takes all of that as flags. It is not a pi-subagents agent, because since 0.43 pi-subagents runs every child through `workflowScript`, which needs `node:v8` promise hooks that the Bun-built Pi lacks. Claude Code's `skills:` field only preloads and Codex agents can only disable inherited skills, so in those harnesses a specialist would read its bundle through an index instead.
- The Blender specialist drives the headless Blender CLI, not Blender MCP: the skills' real work is `bpy` code either way, and the MCP add-on needs a running GUI Blender listening on an unauthenticated socket that executes any Python it receives. The role prompt translates the skills' MCP calls into CLI steps and preview renders.
- `pi-blender` lives in the `blender` aspect's Home Manager half, so a host that installs Blender also gets its agent. Orchestrators call `pi-blender -p "<brief>"`; run bare, it is an interactive session.
- T3 Code runs `pi-blender` as its own Pi provider instance (the Pi driver's `binaryPath`), so an orchestrator delegates to it as a visible child thread. The `blender` aspect declares that instance through `t3code.providerInstances`, which the `t3code` aspect merges into `~/.t3/userdata/settings.json` at activation instead of owning the file, because T3 writes the rest of it.
